# 体适能模拟跑步

一个用于体适能模拟运动的 Python 程序，内置完整的命令行管理系统。

> 适用环境：Python 3.12
> 详细操作请参阅 [`使用手册.md`](使用手册.md)

---

## 功能特性

### 1. 学校管理
- 从服务器获取省份列表，**支持按省份选择更新**（避免一次性拉取全国数据）
- 区分公版（云端部署）与私版（私有部署）学校
- 自动过滤 demo / test 学校，为公版学校抓取内网 URL

### 2. 账号授权
- 用户名 / 密码登录，自动判断公版 / 私版
- **按省份筛选学校**，快速定位目标学校
- 认证信息存入本地 SQLite，支持 Token 刷新

### 3. 跑步功能
- 三种跑步类型：晨跑 / 阳光跑 / 自由跑
- 自定义跑步距离（0~50 公里）
- 智能轨迹生成 + 真实运动模拟（配速、步态、疲劳、撞墙、GPS 噪声）
- 人脸验证支持（开始 / 中途 / 结束，公版）

### 4. 路径爬取
- 从账号历史运动记录中爬取路径数据，供后续复用

### 5. 更新人脸图片
- 从服务器下载账号最新人脸图片并保存到本地

### 6. 查询跑步有效次数和里程
- 统计晨跑 / 阳光跑 / 自由跑有效次数、总有效次数、总里程

## 系统架构

### SDK 三层继承

```
TiShiNengSdkBase (基础层)
    ├── 通用 HTTP 客户端
    ├── MD5 签名生成
    └── 省份 / 学校查询 API
         ↓
TiShiNengSdkPrivate (私版层)         TiShiNengSdkPublic (公版层)
    ├── AES / RSA 加密                ├── OAuth 2.0 认证
    ├── 学校特定端点                  ├── 高级加密（AES + RSA）
    └── 私版跑步记录                  └── 公版跑步记录
```

### 轨迹数据生成链路

```
跑线(queryPath) → track_clean 清洗 → track_resample 采样
    → track_metrics 步态 → tsn_payload 组装 + 自检 → 上传
```

核心设计原则：**几何真值自洽，对外只加小噪声**。

| 模块 | 职责 |
|------|------|
| `track_geo.py` | 几何基础：haversine、折线推进、按距离定位 |
| `track_clean.py` | 跑线清洗：去重复点、去跳点 |
| `track_resample.py` | 采样：配速、首点加速、疲劳衰减、撞墙、GPS 噪声、限速裁剪 |
| `track_metrics.py` | 步态建模：步频、步数桶 |
| `tsn_payload.py` | 载荷组装、人脸公里数定位、提交前自检 |

## 安装

### 环境要求

- **Python 3.12**（`python` 可能指向其他版本，请使用 `python3.12`）
- SQLite（账号与路径数据存储，无需额外配置）

### 安装依赖

```bash
python3.12 -m pip install -r requirements.txt
```

主要依赖：

| 依赖 | 用途 |
|------|------|
| `httpx` | 异步 HTTP 客户端 |
| `pycryptodome` | AES / RSA 加密 |
| `sqlalchemy` + `aiosqlite` | 数据库 ORM / 异步 SQLite |
| `loguru` | 日志记录 |
| `geopy` / `shapely` / `numpy` | 地理与几何计算 |
| `pillow` | 人脸图片处理 |
| `matplotlib`（可选） | 轨迹可视化，未安装时自动降级 |

> ⚠️ `requirements.txt` 为 **UTF-16 LE 编码**，如需手动编辑请用 `encoding='utf-16'` 读写。

## 快速上手

启动主系统：

```bash
python3.12 main.py
```

主菜单（6 项功能）：

```
============================================================
  TiShiNeng 管理系统
============================================================
1. 更新学校列表
2. 授权账号
3. 开始跑步
4. 爬取路径数据
5. 更新人脸图片
6. 查询跑步有效次数和里程
0. 退出系统
============================================================
```

### 标准流程（首次使用）

1. **`1` 更新学校列表** —— 选省份 → 拉取该省学校写入数据库（一次性准备）
2. **`2` 授权账号** —— 选省份 → 选学校 → 输入用户名 / 密码完成认证（一次性准备）
3. **`3` 开始跑步** —— 选账号 → 选跑步类型 → 输入距离 → 确认执行

> 步骤 1、2 完成后账号信息保存在本地数据库，之后每次跑步只需执行步骤 3。

## 离线轨迹模拟（推荐先做）

`simulate_run.py` 可在**不联网、不上传**的情况下生成一条完整轨迹，用于快速验证轨迹质量：

```bash
python3.12 simulate_run.py --km 2.3 --seed 42 --limit-speed 3.3 --faces 1.1,1.6
```

示例输出：

```
=== 模拟结果 ===
配速: 6.75 min/km
里程: 2300.0 m
平均速度: 2.47 m/s
峰值速度: 2.607 m/s
步数桶合计: 2743, 末点: 2743
自检: 0 error / 0 warning
```

轨迹应满足的指标：

| 指标 | 合格标准 |
|------|---------|
| 配速 | 6~7 分钟 / 公里 |
| 超速点 | 0（峰值 < 限速） |
| 采样间隔 | 1~1.3 秒随机抖动 |
| 步数桶 = 末点步数 | 严格一致 |
| GPS 偏移 | 均值 ≤1.2m，最大 ≤3.2m |
| 里程 | ≥ 目标值 |

## 常见问题

**Q1：`pip install` 失败？**
A：确认用 `python3.12 -m pip`；确认 `requirements.txt` 未被误改编码（须为 UTF-16 LE）。

**Q2：授权失败？**
A：检查用户名 / 密码是否正确；确认所选学校类型（公版 / 私版）与实际匹配。

**Q3：跑步提示路径生成失败？**
A：先执行「爬取路径数据」（菜单 `4`）采集该学校的路径，再重新跑步。

**Q4：人脸验证失败？**
A：确认该账号已在 APP 上传过人脸照片；或用菜单 `5` 重新更新人脸图片。

**Q5：数据库提示 `no such column: province_name`？**
A：旧库缺少省份字段，需执行 `ALTER TABLE tsn_school ADD COLUMN province_name VARCHAR(64);`，或删除旧数据库后重新「更新学校列表」。

## 注意事项

1. **教育用途**：本项目仅供学习与研究，请勿用于任何违规目的。
2. **密钥说明**：代码中的 RSA 公钥 / AES 密钥 / API 端点仅为示例，需按实际环境替换。
3. **首次使用顺序**：务必先「更新学校列表」再「授权账号」。
4. **距离设置**：建议 1~10km，过长会显著增加耗时。
5. **隐私保护**：本地数据库（`tsn_data.db`）与人脸图片（`face_images/`）已被 `.gitignore` 排除，**请勿提交至公开仓库**。
6. **日志排查**：出问题时优先查看 loguru 日志输出定位。
